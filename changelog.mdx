<Update label="2026-11-03">
**LinkedIn polls:** publish a poll with `data.LINKEDIN.poll`: a question, 2-4 options and a duration. Polls can't include media or a `link`. See [LinkedIn polls](/api-reference/platforms/linkedin#polls).

**Google Business:** a location reachable through several Google accounts or groups is listed once in `channels`, and refreshing channels keeps the selected location when Google moves it. See [Google Business](/api-reference/platforms/google-business).
</Update>

<Update label="2026-11-02">
**Comments on posts published outside bundle.social:** with Direct Messages or Automations turned on, new Instagram, Facebook and TikTok comments arrive in real time on every post, including posts published directly in the app. In `comment.received` they have `postId: null` and a `comment.importedPostId`. See [Comments](/api-reference/comments).

**Comment automations on all posts:** `postId` is now optional in a `COMMENT_CREATED` trigger. Without it the flow covers every post on the account; a post's own matching flow takes priority. See [Comment Flows](/api-reference/automations/how-flows-behave#comment-flows).

**Message and automation usage:** new `GET /api/v1/organization/usage/messages` shows messages and automation runs used and allowed this month, per account. See [Rate Limits](/api-reference/rate-limits#check-monthly-message-and-automation-usage).

**TikTok:**
- Location tags with `locationId` and `locationName`, searchable with `GET /api/v1/misc/tiktok/locations`. See [Location tags](/api-reference/platforms/tiktok#location-tags).
- Photo Mode: up to 35 images (was 10), captions up to 4,000 characters and a `title` of up to 90.

**LinkedIn analytics:** organization video posts now report `views` and `viewsUnique` instead of `0`, and raw data adds video watch time. See [LinkedIn](/api-reference/platforms/linkedin).

**Snapchat:** videos can be up to 400 MB (was 100 MB). See [Snapchat](/api-reference/platforms/snapchat).

**YouTube:** uploads are now capped per organization per day (`YT:orgDailyUploadLimit`), and when YouTube's own quota runs out they fail right away with `YT:uploadCapacityExhausted`. See [Errors](/api-reference/errors#youtube).
</Update>

<Update label="2026-10-29">
**Threads profile views over 2 years again:** profile `views` is summed over the last 2 years (never before April 13, 2024) instead of 365 days. We now read the series in 90-day slices, because Threads kept failing on long views series for some profiles, which stopped their daily account analytics. Affected profiles resume on the next daily run. See [Threads](/api-reference/platforms/threads#profile-analytics).

**An expired token no longer stops account analytics:** a failed refresh caused by an expired or revoked token is now retried on the next daily run instead of switching account analytics off. Accounts switched off this way during the token refresh problem on October 8-9 (mostly YouTube) are collecting again. See [When collection stops for an account](/api-reference/analytics#when-collection-stops-for-an-account).

**Facebook Page posts accept up to 10 images**, as documented, instead of 4. See [Facebook](/api-reference/platforms/facebook).

**TikTok comment import on a deleted video:** the import now ends right away with `status: "FAILED"` instead of retrying. Comments already imported are kept.
</Update>

<Update label="2026-10-28">
**Direct Messages and Automations are out of beta.** Both are part of the paid plans and are turned on per organization on request: [contact us](https://bundle.social/contact) with your organization ID. Access is now per platform: one switch for Instagram and Facebook (DMs and automations), a separate one for TikTok automations, so a TikTok-only setup no longer needs the Meta switch and the other way around.

**Status code change:** while access is not turned on, the [Direct Messages](/api-reference/direct-messages) and [Automations](/api-reference/automations) endpoints now answer `403` with a message that says how to request access, instead of `404`. A wrong ID still returns `404`. If your integration treated `404` as "not enabled", check for `403` as well.

**Automations across organizations:** `POST /api/v1/automations/copy` now returns `{ items, total, skipped }` and leaves out flows whose platform isn't turned on; `GET /api/v1/automations` hides them too. See [Managing Flows](/api-reference/automations/managing-flows).

**Instagram tags and location no longer fail a post:** rejected tags, collaborators or `locationId` are dropped and the post is published, with a warning in `errors.INSTAGRAM`. See [Instagram](/api-reference/platforms/instagram).

**Facebook video titles:** a `mediaTitle` over 255 bytes is cut to fit instead of failing the publish.

**Comment import:** an empty re-import no longer marks the post's stored comments as deleted, and TikTok errors are no longer read as zero comments.
</Update>

**Post history import on TikTok:** imports no longer stop after 3 pages of posts you already have. See [What `count` means](/api-reference/import-posts#what-count-means-and-onlylatest).

<Update label="2026-10-25">
**TikTok posting options:** new `GET /api/v1/misc/tiktok/post-settings?teamId=...` returns the privacy levels the account accepts (`privacyLevelOptions`), whether comments, Duets and Stitches can be turned on (`commentDisabled`, `duetDisabled`, `stitchDisabled`) and the longest video it can publish (`maxVideoPostDurationSec`), read live from TikTok. Use it to build your composer's options. See [TikTok](/api-reference/platforms/tiktok#posting-options-of-an-account).

**Instagram story replies and mentions in Direct Messages:** a reply to the account's story carries `platformData.storyReply` (`storyId`, `url`, `linkStickerUrl`), and a story that mentions the account arrives as an attachment with `type: "STORY_MENTION"`. Story URLs expire with the story. When a message is unsent, `storyReply` is cleared along with `text` and `attachments`. See [Story replies and mentions](/api-reference/direct-messages/conversations#story-replies-and-mentions).

**YouTube post visibility:** profile posts now have `extraData.visibility` (`PUBLIC`, `UNLISTED`, `PRIVATE`), set on import and updated on every analytics refresh. Private and unlisted videos keep refreshing. See [YouTube](/api-reference/platforms/youtube#quirks).

**Raw analytics:**
- **Instagram:** `demographics.follows_and_unfollows` is now requested by follow type, with a parsed `demographics.follows_and_unfollows_by_follow_type` (`follows`, `unfollows`, `unknown`; `null` under 100 followers). See [Instagram](/api-reference/platforms/instagram).
- **Facebook Pages:** `pageInsights` adds `page_daily_follows_unique`, `page_daily_unfollows_unique`, `page_post_engagements` and `page_total_actions`.
- **Facebook views breakdown:** Page and post raw analytics include `mediaViewBreakdowns`, splitting views into paid vs organic (`isFromAds`) and followers vs non-followers (`isFromFollowers`). Views only, not unique reach. See [Facebook](/api-reference/platforms/facebook#raw-analytics).

**Facebook analytics:**
- Reels now get reach (`impressionsUnique`), read from the reel's page post.
- Story analytics (views, unique views) are read during post history import, since stories expire after 24 hours. Force refresh of story analytics is still not supported.

**Post import:** Facebook imports skip unpublished video-library items (drafts, scheduled, ad-only). With imported-posts analytics enabled, imported Facebook and Instagram posts get their first analytics from the regular refresh instead of a placeholder snapshot with zero reach. See [Imported post analytics](/api-reference/import-posts#imported-post-analytics).

**Webhooks:** `socialAction.details.providerError` in `social-account.updated` now includes the platform's `code`, `subcode`, `type` and `fbtraceId` when the platform provides them, next to `message` and `httpStatus`. See [Remote Disconnection Detection](/api-reference/webhooks#remote-disconnection-detection).

**Threads:** the profile post count retries Threads' random errors instead of failing.

**Hosted connect portal:** now loads on older iOS Safari (iOS 15).

**Docs:** how to use `referenceKey` for safe post-create retries. See [Safe retries](/api-reference/examples#safe-retries-with-referencekey).
</Update>

<Update label="2026-10-24">
**Meta reliability:** Facebook, Instagram and Threads calls hold up better under load. The connection pool is bounded, every request has an end-to-end deadline, and token checks are retried on transient Meta errors.

**Threads account analytics:** `views` is now summed over the last 365 days instead of about 2 years, because Threads fails on the longer series. Account-level Threads `views` drop once as a result. Likes, replies, reposts, quotes and followers are unchanged. See [Threads](/api-reference/platforms/threads).

**API errors:** endpoints can now return `503` or `504` when a platform is temporarily unavailable or timed out, instead of a generic `500`. Both are safe to retry with backoff. See [HTTP Status Codes](/api-reference/errors#http-status-codes).

**Direct Messages setup:** messaging now requires the `pages_manage_metadata` permission; without it, enabling messaging returns `400` instead of `502`. Reconnect accounts connected long ago. See [Setup](/api-reference/direct-messages/setup).
</Update>

<Update label="2026-10-17">
**Instagram and Threads: posts deleted on the platform:** posts you delete on Instagram or Threads now get `externallyDeletedAt` set on the next analytics refresh and stop being refreshed, like TikTok and YouTube already did. Applies to published and imported posts. Instagram and Threads return the same error for a deleted post and for one the account can't access, so a post is only marked when it's also missing from the account's own post list. Very old posts (beyond the account's latest ~500 on Instagram, ~1,000 on Threads) aren't checked. See [Analytics](/api-reference/analytics).

**Threads analytics:** fixed account and post statistics failing with `Something went wrong, please try again later.` Threads' insights API currently fails at random on a share of requests; we now retry those reads automatically, so stats that were stuck fill in on the next refresh. Publishing wasn't affected.
</Update>

<Update label="2026-10-16">
**Instagram Stories import:** Stories imported through post history now come with their numbers (views, reach, replies, shares), read from Instagram at import time. A Story that Instagram has no insights for is imported without analytics instead of with zeros.

**Threads:** reposts imported before the Oct 14 fix (which never get statistics) are removed from imported posts and no longer refreshed.
</Update>

<Update label="2026-10-15">
**Facebook and Instagram comments:** fixed comments occasionally being posted twice. When creating a comment took too long (usually while Facebook built a link preview), our request timed out, the comment still got created, and the automatic retry posted it again. Before an automatic retry we now check whether the comment already exists on the post (or under the parent comment) and, if it does, adopt it instead of posting again; if that check can't run, the retry waits rather than risk a duplicate. Comment creation also gets more time, so these retries are much rarer.

**Instagram reconnect:** a reconnect (`reconnect: true`) now always asks Instagram for a fresh login, so it can't silently reuse a different account the browser is logged into.
</Update>

<Update label="2026-10-14">
**Instagram reconnect in place:** `POST /api/v1/social-account/connect` accepts `reconnect: true` to re-authorize the Instagram account already connected to a team, instead of disconnecting it. Tokens and permissions are refreshed; the account, its draft and scheduled posts stay. In the dashboard and hosted portal, open **Disconnect** and choose **Reconnect**. Supported for Instagram connected with Instagram login (`instagramConnectionMethod: "INSTAGRAM"`); the user must log in with the same account (`instagram-reconnect-different-account` otherwise). See [OAuth Options](/api-reference/connect-social-accounts/oauth-options#reconnect).

**Instagram login:** connecting now fails with `instagram-not-enough-permissions` when the publish permission isn't granted, instead of connecting an account that can't publish.

**Google Business:**
- An unticked "Google Business listings" permission on the consent screen now returns `google-business-not-enough-permissions` instead of the generic `google-business-callback`. See [Callback Parameters](/api-reference/connect-social-accounts/callbacks).
- `userId` is always Google's own account id; a connection without one now fails instead of storing a placeholder.
- `refresh-channels` clears the selected location when the login no longer has access to it, so the account asks for a new one.
- Docs: `OFFER` posts need `eventStartDate` and at least one offer field, and can't have a call-to-action button. See [Google Business](/api-reference/platforms/google-business).

**Threads:** reposts no longer count toward the profile's post count and aren't imported as your own posts.

**Pinterest:**
- Per-pin raw analytics are now stored, so the raw endpoints return pin clicks, outbound clicks, impressions and saves (from the next refresh).
- Video Pins now get Pinterest's video metrics (`VIDEO_START`, `VIDEO_MRC_VIEW`, watch time), so `views` is filled for video Pins.

**TikTok + other platforms:** a post no longer ends in `ERROR` when TikTok confirms publication a few seconds after our first status check, while the other platforms are still publishing.
</Update>

<Update label="2026-10-13">
**Deprecation:** the `teams` array in `GET /api/v1/organization` is deprecated and will be **removed on November 15, 2026**. It isn't paginated and gets slow for organizations with many teams. List teams with the paginated `GET /api/v1/team` instead (`offset`, `limit`, optional `search`; returns `{ items, total }`). The rest of the organization response stays the same. See [Finding your team IDs](/api-reference/introduction#finding-your-team-ids).

**Post import:** new `onlyLatest` option. With `onlyLatest: true`, an import checks only the latest `count` posts and imports the ones you don't have yet, so a daily sync with nothing new imports nothing and uses none of your limit. Without it, `count` still means "`count` posts you don't have yet", going further back if needed. See [What `count` means](/api-reference/import-posts#what-count-means-and-onlylatest).

**YouTube thumbnails:** when YouTube rejects a custom thumbnail, we now retry it a few times (YouTube often refuses it while a new video is still processing). If it still fails, the post stays `POSTED` and YouTube's reason shows up in `errors.YOUTUBE`, instead of the thumbnail silently going missing.
</Update>

<Update label="2026-10-10">
Google review imports: `count` is now the number of **new** reviews to import. Reviews you already have are refreshed but skipped, so re-running an import continues into older reviews until it has `count` new ones or Google has no more, instead of stopping after the newest page. Only new reviews use up the monthly import limit. See [Google Business Reviews](/api-reference/platforms/google-business-reviews).

YouTube: Shorts are now correctly flagged (`contentType: "SHORTS"`, `isShort: true`) and get `/shorts/<id>` links. Re-running a post history import also updates `permalink` and `extraData` on posts you already imported, so existing Shorts pick up the right link.

Instagram raw analytics: `reachByFollowType` now covers the last 30 days, the same window as `totals30d`, instead of only the last 24 hours.
</Update>
