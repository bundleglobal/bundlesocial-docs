`bundlesocial-mcp` is a [Model Context Protocol](https://modelcontextprotocol.io) server that exposes the bundle.social operations as MCP tools - so Claude, ChatGPT, Claude Code, Cursor, Codex, VS Code, Gemini CLI and any other MCP client can post, schedule, import, analyze content and manage connected accounts across 14+ platforms.

Use it as a **hosted server** at `https://mcp.bundle.social` (nothing to install: paste the URL and sign in with your bundle.social account, or send an API key) or run it as a **local stdio server** (`npx bundlesocial-mcp`). Both expose the same tools; the local server can also read files from your disk.

## Tools

Dedicated tools cover the everyday work below. Everything else in the public API (editing or deleting published posts per platform, YouTube playlists, Google Business profile, reviews and recommendations, direct messages, automations, credits) is reachable through `search_api_actions` and `call_api_*`, so the whole API is available to an agent.

**Diagnostics & discovery**

| Tool | Description |
|---|---|
| `check_setup` | Diagnostic JSON: connection or API key, connectivity, organization API access, team selection, integrations, quotas. |
| `list_integrations` | List connected social accounts (ids, platform types, channels). |
| `list_integration_tools` / `trigger_integration_tool` | List & call read-only platform helpers - subreddit flairs/requirements, YouTube categories/playlists/regions, LinkedIn mentions, Instagram locations/audio/business discovery, Google Business categories, TikTok trending music. |

**Posts**

| Tool | Description |
|---|---|
| `create_post` / `schedule_post` | Publish now (or as a draft) / schedule for a future date. |
| `update_post` / `retry_post` | Update a post (only changed fields) / re-attempt one that ended in `ERROR`. |
| `get_post_by_reference_key` | Fetch a post by the `referenceKey` set on it instead of its bundle.social id. |
| `list_reconnect_candidates` / `reconnect_posts` | List posts that lost their social account after a disconnect, and reattach them to a newly connected account. |
| `list_posts` / `get_post` / `delete_post` | List with filters / fetch / delete posts. |
| `create_post_import` … | Import post history from a connected account: `create_post_import`, `list_post_imports`, `get_post_import`, `list_imported_posts`, `delete_imported_posts`, `retry_post_import`. |
| `create_post_csv_import` … | Bulk-schedule from a CSV (URL or local file): `create_post_csv_import`, `list_post_csv_imports`, `get_post_csv_import`, `get_post_csv_import_status`, `get_post_csv_import_rows`. |

**Comments**

| Tool | Description |
|---|---|
| `create_comment` / `list_comments` / `get_comment` / `update_comment` / `delete_comment` | Comment on a post (pass `content` multiple times for a chain) / list / fetch / update / delete comments. |
| `create_comment_import` … | Pull existing comments for a post: `create_comment_import`, `list_comment_imports`, `get_comment_import`, `list_imported_comments`. |
| `act_on_imported_comment` | Moderate an imported comment - delete, hide/unhide, like/unlike, approve/reject. |

**Media**

| Tool | Description |
|---|---|
| `upload_media` | Upload an image/video/document from a URL (or local path in stdio mode); local files over ~90 MB go straight to storage automatically. |
| `init_large_upload` / `finalize_large_upload` | Direct upload of any file up to 5 GB: `init` returns a signed `url`, PUT the bytes there (e.g. `curl -X PUT --upload-file`), then `finalize`. This is how an agent with a shell sends a local file to the hosted server. |
| `list_media` / `get_media` / `delete_media` / `delete_media_many` | List / fetch / delete uploads. |

**Integrations (social accounts)**

| Tool | Description |
|---|---|
| `connect_integration` / `disconnect_integration` | Start an OAuth connect flow (returns a URL) / disconnect an account. |
| `create_integration_portal_link` | Hosted portal link for end users to connect accounts. |
| `set_integration_channel` / `unset_integration_channel` / `refresh_integration_channels` | Pick / clear / refresh the channel (page, board, server channel) for an account. |
| `check_integration_connection` / `refresh_integration_profile` / `get_integration_by_type` / `copy_integration` / `list_integrations_to_delete` | Connection check, profile refresh, lookup by platform, copy between teams, list accounts pending deletion. |

**Analytics**

| Tool | Description |
|---|---|
| `get_post_analytics` | Per-post engagement metrics (`raw: true` for the unprocessed payload). |
| `get_account_analytics` | Latest analytics for a connected account by `platform` (`raw: true` for the unprocessed payload). |
| `get_bulk_post_analytics` | Engagement metrics for several posts at once. |
| `refresh_analytics` | Force a fresh pull - by `postId` for a post, otherwise `platform` for an account. |
| `get_analytics_summary` | Org-level usage quotas + latest per-integration analytics snapshot. |

**Teams & organization**

| Tool | Description |
|---|---|
| `list_teams` / `get_team` / `create_team` / `update_team` / `delete_team` | Manage teams. |
| `get_organization` / `get_usage` | Your organization, and posts/comments/uploads/messages/imports usage & quotas. |
| `get_daily_limits_usage` | A connected account's daily post/comment allowance for a given day. |

**Everything else in the API**

| Tool | Description |
|---|---|
| `search_api_actions` | Search all ~200 public API actions by keyword. A narrow search returns each action's parameters. |
| `call_api_read` | Run a read action by id, with a flat `params` object. |
| `call_api_action` | Run an action that changes data (marked destructive, so clients can ask for confirmation). |
| `get_credit_balance` / `quote_billable_usage` | Prepaid credit balance for X (Twitter) pay-per-use actions, and a price quote before running them. |

Errors come back as `{ "error": { "code", "message", "details"? } }` with `isError: true`. The per-platform fields for posts are documented in [Platform parameters](/api-reference/platform-parameters).

## Configuration

### Hosted server: sign in

Add `https://mcp.bundle.social` to your client. The first time it connects, it opens bundle.social in your browser: sign in, choose **Full access** (post, schedule, reply, upload) or **Read only** (posts, comments and analytics), optionally pick a default team, and click **Allow**. There is no key to copy. Only the organization's owner can allow access for now.

Every connected app is listed in [Connected apps](https://bundle.social/dashboard/organization/connected-apps), where you can disconnect it; the app then asks you to sign in again. Changing your password or email, or resetting your password, in the dashboard disconnects all your apps.

<Tabs>
  <Tab title="Claude">
    On claude.ai or in Claude Desktop, open **Customize → Connectors**, click **+ Add**, then **Add custom connector**:

    - Name: `bundle.social`
    - URL: `https://mcp.bundle.social`
    - Leave the advanced settings empty.

    Click **Add**, then **Connect**. The connector works in Claude Desktop, on claude.ai and in the mobile apps.
  </Tab>
  <Tab title="ChatGPT">
    In **Settings → Apps & Connectors**, turn on **Developer mode** under **Advanced settings**, then create an app:

    - Name: `bundle.social`
    - MCP server URL: `https://mcp.bundle.social`
    - Authentication: **OAuth**

    Confirm the warning, click **Create**, then **Connect**. Right after connecting, ChatGPT may need a second message before it lists the tools.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http bundlesocial https://mcp.bundle.social
    ```
    Then type `/mcp` in Claude Code, pick `bundlesocial` and choose **Authenticate**. The config holds no secret, so `--scope project` can share it in the project's `.mcp.json`.
  </Tab>
  <Tab title="Cursor">
    `~/.cursor/mcp.json` (global) or `.cursor/mcp.json` (project):
    ```json
    {
      "mcpServers": {
        "bundlesocial": { "url": "https://mcp.bundle.social" }
      }
    }
    ```
    Then open **Cursor Settings → MCP** and click **Connect** next to `bundlesocial`.
  </Tab>
  <Tab title="Codex">
    `~/.codex/config.toml`:
    ```toml
    [mcp_servers.bundlesocial]
    url = "https://mcp.bundle.social"
    ```
    Then sign in:
    ```bash
    codex mcp login bundlesocial
    ```
  </Tab>
  <Tab title="Other clients">
    Point any client that supports remote MCP servers (Streamable HTTP) at `https://mcp.bundle.social`. A client that supports MCP sign-in (OAuth) opens bundle.social for you to sign in; for one that doesn't, use an API key below.
  </Tab>
</Tabs>

### Hosted server: API key

Use an API key for scripts, scheduled agents and anything that runs without you, and for clients where sign-in isn't available. We recommend a key for VS Code and Gemini CLI. Get one in the [dashboard](https://bundle.social/dashboard/organization/api-keys) and put it in place of `YOUR_API_KEY`. A key covers the whole organization and stays valid until you delete it.

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http bundlesocial https://mcp.bundle.social \
      --header "Authorization: Bearer YOUR_API_KEY"
    ```
    In a committed `.mcp.json`, write the header as `Bearer ${BUNDLESOCIAL_API_KEY}` and set that variable on each machine.
  </Tab>
  <Tab title="Claude Desktop & claude.ai">
    In **Add custom connector**, use `https://mcp.bundle.social`, choose **No sign-in**, and under **Request headers** add `Authorization` = `Bearer YOUR_API_KEY`. Claude may tag **Sign in now** as Detected; with a key, choose **No sign-in** anyway.
  </Tab>
  <Tab title="Cursor">
    ```json
    {
      "mcpServers": {
        "bundlesocial": {
          "url": "https://mcp.bundle.social",
          "headers": { "Authorization": "Bearer YOUR_API_KEY" }
        }
      }
    }
    ```
    To keep the key out of the file, write the value as `Bearer ${env:BUNDLESOCIAL_API_KEY}`.
  </Tab>
  <Tab title="VS Code">
    `.mcp.json` at the workspace root, or `~/.copilot/mcp-config.json` for every workspace. VS Code reads `${BUNDLESOCIAL_API_KEY}` from your environment, so the file is safe to commit:
    ```json
    {
      "mcpServers": {
        "bundlesocial": {
          "type": "http",
          "url": "https://mcp.bundle.social",
          "headers": { "Authorization": "Bearer ${BUNDLESOCIAL_API_KEY}" }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Codex">
    `~/.codex/config.toml`, with your key exported as `BUNDLESOCIAL_API_KEY`:
    ```toml
    [mcp_servers.bundlesocial]
    url = "https://mcp.bundle.social"
    bearer_token_env_var = "BUNDLESOCIAL_API_KEY"
    ```
  </Tab>
  <Tab title="Gemini CLI">
    ```bash
    gemini mcp add --transport http \
      --header "Authorization: Bearer YOUR_API_KEY" \
      bundlesocial https://mcp.bundle.social
    ```
    In `settings.json`, use `httpUrl` (not `url`, which is the older SSE transport) and `headers`.
  </Tab>
  <Tab title="Other clients">
    Send the key as `Authorization: Bearer YOUR_API_KEY` (or `x-api-key: YOUR_API_KEY`). Agents built on the Claude, OpenAI or xAI APIs take the same URL and key in their remote MCP tool settings.
  </Tab>
</Tabs>

The hosted server can't read files from your disk: pass media and CSV files as public `https://` URLs, or let an agent with a shell use `init_large_upload`.

### Teams

A connection or key covers every team in your organization. Name the team in your prompt ("post this for the Acme team"): every team-scoped tool accepts a team id or the exact team name. When you sign in you can pick a default team; with an API key, send an `x-bundle-team-id` header to the hosted server, or set `BUNDLESOCIAL_TEAM_ID` for the local server.

### Local server

Reads `BUNDLESOCIAL_API_KEY` (required), `BUNDLESOCIAL_TEAM_ID` (optional default team) and `BUNDLESOCIAL_API_URL` (optional). Needs Node.js 20+.

<Tabs>
  <Tab title="Claude Desktop">
    `claude_desktop_config.json` (macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`):
    ```json
    {
      "mcpServers": {
        "bundlesocial": {
          "command": "npx",
          "args": ["-y", "bundlesocial-mcp"],
          "env": { "BUNDLESOCIAL_API_KEY": "YOUR_API_KEY" }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add bundlesocial --env BUNDLESOCIAL_API_KEY=YOUR_API_KEY -- npx -y bundlesocial-mcp
    ```
  </Tab>
  <Tab title="Cursor">
    ```json
    {
      "mcpServers": {
        "bundlesocial": {
          "command": "npx",
          "args": ["-y", "bundlesocial-mcp"],
          "env": { "BUNDLESOCIAL_API_KEY": "YOUR_API_KEY" }
        }
      }
    }
    ```
  </Tab>
</Tabs>
